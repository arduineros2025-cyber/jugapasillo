# Arquitectura desde un manual de producto

1. Leé las fuentes del producto, requisitos y restricciones; separá lo explícito de las inferencias.
2. Definí usuarios, recorridos, pantallas, navegación, entidades, permisos, estados y criterios del MVP.
3. Revisá el repositorio existente y su stack; preservá decisiones ya tomadas y evitá sobreingeniería.
4. Para una aplicación nueva, proponé un mapa de rutas y componentes; después prepará la estructura inicial si el usuario autorizó construir.
5. No dediques tiempo al pulido visual antes de ordenar navegación y datos, salvo que el usuario pida expresamente un prototipo visual.
6. Documentá decisiones duraderas en los archivos del proyecto y registrá las incertidumbres que realmente requieren una definición.
7. Si el proyecto requiere cambios grandes o irreversibles, presentá un plan revisable antes de implementarlos.
