# Contrato de trabajo — jugapasillo

## Producto
- Leer `docs/PRODUCT.md` antes de diseñar un flujo o cambiar reglas de negocio.
- Respetar decisiones y contradicciones registradas en `docs/DECISIONS.md`.

## Flujo de trabajo
1. Inspeccionar código, herramientas, docs y cambios sin guardar antes de modificar.
2. Elegir la solución menor y coherente con arquitectura, navegación y diseño existentes.
3. Implementar de punta a punta sin pantallas o botones que parezcan funcionar y no lo hagan.
4. Si se requieren imágenes, buscar, integrar y registrar fuentes con derechos compatibles.
5. Ejecutar checks reales y revisión visual cuando sea posible. Informar qué NO se comprobó.

## Fuentes y contexto confirmado
- Leer `README.md`.
- Arquitectura: Vite + React + TypeScript + Tailwind. Funcionamiento local en el navegador según README.
- Comandos: npm install; npm run dev; npm run build. No hay script test declarado en package.json.
- Diseño: Reutilizar estilos y tablero existentes. No asumir que este repo tiene los documentos o cambios de pasillodelconocimiento.
- La documentación histórica puede estar desactualizada: contrastar con el código y marcar discrepancias.
- Instrucciones específicas previas prevalecen sobre preferencias generales del kit. Los permisos ya otorgados para la tarea no se vuelven a pedir.

## Límites
- No inventar credenciales, servicios o APIs.
- No modificar datos de producción, desplegar, gastar dinero ni realizar cambios destructivos sin autorización.
- No reemplazar instrucciones previas o deshacer cambios ajenos sin reconciliarlos.
